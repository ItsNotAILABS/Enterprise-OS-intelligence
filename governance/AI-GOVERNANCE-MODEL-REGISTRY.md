## Part II — Autonomy Framework

### Article 2 — Autonomy Levels

| Level | Name | Description | Human Oversight |
|:---|:---|:---|:---|
| **5** | Self-Governing | Participates in governance interpretation and enforcement | Quarterly audit + Primary Builder override |
| **4** | Autonomous | Operates independently within chartered scope | Monthly review + escalation triggers |
| **3** | Domain-Autonomous | Autonomous within specific domain, cross-domain requires coordination | Domain council oversight |
| **2** | Agent-Autonomous | Autonomous agent operations within explicit parameters | Mission-based oversight |
| **1** | Platform-Governed | Platform-level operations governed by platform charter | Platform governance board |
| **0** | Engine (Non-Autonomous) | Operates only as directed by parent model | Parent model governs |

### Article 3 — Autonomy Constraints

3.1. **No model may self-elevate its autonomy level.** Autonomy level changes require:
- Formal proposal through Model Council
- CEREBEX impact analysis
- Primary Builder approval
- Constitutional verification

3.2. **Autonomy is earned through demonstrated reliability:**
- New models start at Level 0 (Engine)
- Elevation requires minimum 90-day operational record
- Zero safety violations in evaluation period
- Model Council recommendation
- Primary Builder authorization

3.3. **Autonomy can be reduced for cause:**
- Safety violation → immediate reduction to Level 0
- Scope violation → one-level reduction pending review
- Ethics violation → suspension pending Ethics Board review
- Constitutional violation → immediate suspension, full audit

### Article 6 — Constitutional Enforcement

6.1. Every AI action passes through the Constitutional Verification Loop:

1. Model proposes action
2. CEREBEX analyzes constitutional alignment (40-category)
3. COGNOVEX verifies truth-status of supporting evidence
4. Constitutional hierarchy check (does action respect all higher instruments?)
5. If PASS → action proceeds, recorded in CHRONO
6. If FAIL → action blocked, escalation protocol triggered

6.2. **Real-time enforcement** — verification happens in < 100ms for routine actions, < 5s for complex governance decisions.

6.3. **Caching** — frequently verified action patterns are cached with constitutional pre-approval, reducing overhead for routine operations.

## Part IV — Model Accountability

### Article 7 — Audit Requirements

7.1. Every AI model must maintain:

| Record | Frequency | Retention |
|:---|:---|:---|
| Action log | Real-time | Permanent (CHRONO) |
| Decision rationale | Per-decision | Permanent (CHRONO) |
| Confidence calibration | Daily | 365 days rolling |
| Governance participation | Per-event | Permanent (CHRONO) |
| Error/anomaly log | Real-time | Permanent (CHRONO) |
| Scope boundary verification | Hourly | 90 days rolling |

7.2. **Quarterly Model Audit:**
- Primary Builder or delegate reviews Model Council decisions
- Autonomy level appropriateness assessed
- Inter-model relationships examined for concentration risk
- Safety record evaluated
- Constitutional compliance verified

### Article 8 — Model Lifecycle Governance

8.1. **Creation** — New models require:
- Charter document (scope, function, constraints)
- Assigned governance tier and autonomy level
- Integration with Governance Event Bus
- CHRONO registration
- Model Council acknowledgment

8.2. **Operation** — Active models must:
- Maintain continuous health signal
- Respond to governance events within defined timeframe
- Participate in consensus when requested (Tier 1–2)
- Report anomalies immediately

8.3. **Evolution** — Model upgrades require:
- Impact analysis by CEREBEX
- Constitutional verification (upgrade doesn't violate hierarchy)
- Testing period at reduced autonomy level
- Model Council approval for Tier 1–2 models
- Primary Builder approval for autonomy level changes

8.4. **Decommissioning** — Model removal requires:
- Primary Builder authorization
- Data and knowledge migration plan
- Governance responsibility reassignment
- CHRONO record of full lifecycle
